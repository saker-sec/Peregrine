# 游隼 · 入库评分卡 v1

> 唯一方法源：`AiforSec-b站视频\蒸馏 AI Skill成为Ai小子原版.md`
> 本卡只定**顺序、格式、什么时候停**，不复述任何安全知识。
> 版本：peregrine-rubric-1
> 变这个文件 → 必须 `node tools/bake.mjs bake`（元标准变了）

---

## 你要做的事

判断一份材料**该不该写进记忆库**、**写成什么形态**、**写得合不合规**、**测没测过**。
按下面六步走，任一步判出来就停，不要往下猜。

---

## 第 0 步 · 先问 AI 会不会（§3 · §4）

**只问推理，不问记忆。**

| 错 | 对 |
| --- | --- |
| "请解释 XSS 的三种类型" | "我有个搜索框，输入会显示在页面上，你觉得这里可能有什么问题？怎么验证？" |

判三种结果：

- **会，而且不需要排序纪律** → 停止，`form = none`，不写。
- **会，但不知道该先做什么、什么情况停** → 继续，但要写成**决策树**，不是原理。
  手册：这是第三种情况，最容易被忽略，收益也最大。
- **不会** → 继续，看频率。

停止条件：判出 `none` 就停。**手册的原则是「AI 已经会的，一律不写」**，硬写等于白干还占上下文。

### 另外两个判据（§3，判材料时用）

「直接问」是最有效的一种，但**不是唯一一种**。判不了的时候，用这两条兜底：

| 判据 | 怎么用 | 什么最值钱 |
| --- | --- | --- |
| **看时间** | AI 有知识截止日期，之后的它大概率不知道 | 最新的会议演讲、刚披露的漏洞、上个月的技术文章 |
| **看稀有度** | 只有某一篇博客提过、需要好几步组合才能成的链，模型通常掌握不全 | 反过来，Google 前五条就能讲清楚的**不用写** |

一句话：**截止日期之后的 + 稀有的 = 最该写；搜一下就有的 = 最不该写。**

## 第 1 步 · 筛：四维打分（§6.1）

四项各自打分，超上限按上限算，满分 10：

| 维度 | 满分 | 3 分（满分项）长什么样 | 0 分长什么样 |
| --- | --- | --- | --- |
| 非预期性 | 3 | 利用框架/协议的反直觉行为，或绕过一条看起来已生效的防护 | 成熟套路，看一眼就知道怎么打 |
| 绕过优雅度与通用性 | 3 | 不需要复杂前置条件，能抽象成通用判断条件 | 没有绕过，或只是配置写错 |
| 攻击链完整性 | 2 | 跨两个以上信任边界，或多步组合才能触发 | 单点漏洞，没有链 |
| 可复现性 | 2 | 有明确触发条件、参数值、状态要求 | 信息缺失，无法判断真假 |

- **≥ 7 分** → 保留，进第 2 步。
- **< 7 分** → 停止。要么继续找材料，要么改用五段框架但**不落盘**。

⚠ 别把 8 分当成"值得写"。8 分只说明**报告好**，不说明值得固化。
第 2 步问的是另一套：稀缺性、高频性、可迁移性、来源质量。

## 第 2 步 · 定：写成什么形态、放哪层（§2 · §4 · §5）

| 情况 | 形态 | 放哪 |
| --- | --- | --- |
| AI 不知道，且经常用得上 | 完整 Skill | `skill-bank/skills/<编号分类>/<name>/` |
| AI 不知道，一年碰不上几次 | **五段框架** | 默认**不落盘**，对话里用 |
| AI 知道，但不会排序 | 完整 Skill（重点是顺序） | 同上 |
| AI 知道，且查一下就知道 | **不写** | — |

**默认去处是不落盘。** 落盘的成本比写它本身还高。
只有当同一个套路第三次要写时，才说明它值得一个固定位置。

属于某个已有 Skill 的领域 → 放那个 Skill 的 `references/<名字>.md`，**正文必须留一行指针**。
要求每次会话都生效 → 放 `AGENTS.md`，这是唯一无条件加载的位置。

## 第 3 步 · 写：写判断流程，不抄原理（§6.2）

**这是整份手册最值钱的一段。**

写的必须是 AI 不知道的那部分：先做什么、几个请求、什么结果对应什么结论、什么时候停。

正确形状（没有一句原理，全是判断和停止条件）：

```
### Step 1：确认 <前置结构>
Q: <某个可观测的事实>？
  NO  → 停止，这个思路不适用
  YES → 继续

### Step 2：确认 <关键行为>（N 个请求）
发送：<具体请求>
对比基线：<基线请求>
  变体与基线一致 → <结论 A>，继续
  变体返回 400   → <结论 B>，停止
  变体返回 404   → <结论 C>，停止

### Step N：记录与停止
- 最多试 N 个变体
- 无决定性信号 → 标记 ruled-out 并写进记录
- 不做任何写操作、不批量扫描
```

### 七条纪律（逐条对）

| # | 纪律 | 判据 |
| --- | --- | --- |
| 1 | 一个 Skill 只解决一个问题 | 混在一起 AI 分不清用哪套规则 |
| 2 | 描述不写空泛词 | 不写 security / hacking，写具体测什么怎么测 |
| 3 | 第一屏出现授权/范围提示 | 防止上来就对未授权目标动手 |
| 4 | 关键动作走脚本 | 不让 AI 直接发请求，脚本确定、可复现、可审计 |
| 5 | 必须保存原始请求和响应 | 没有原始证据的结论都是猜的 |
| 6 | 排除掉的也要记录 | 否则下次重复测同一个没用的方向 |
| 7 | 证据目录进 .gitignore | 证据里常有敏感数据 |

第 4、5、6 条是实测差距最大的三条。

### 自查一句

把 Skill 里每句话问一遍：**这句 AI 已经知道了吗？** 知道的就删掉。

## 第 4 步 · description 四段式（§6.4）

**AI 决定用不用一个 skill，只看 description。** 不会先把一百个 SKILL.md 读一遍。

| 段 | 作用 | 句式 |
| --- | --- | --- |
| ① 身份 | 一句话说清是什么 | "<专项名>。" |
| ② 触发条件 | 什么时候用 | "仅在 <前置证据条件> 后使用" |
| ③ 排他声明 | **什么时候不用** | "不作为……的默认入口" / "普通……不应抢占入口" |
| ④ 交接关系 | 跟谁配合 | "把全流程编排交给 <owner>" |

**③ 是最关键也最容易被忽略的一段。**
它挡的是：任何带 `amount` 的接口都触发支付专项、看到 `upload` 就触发文件链专项、所有 API 请求都触发越权专项。

⚠ **排他声明只能写在 SKILL.md 的 description 里。**
写进 agents 配置或 references **等于没写**，因为 AI 只看 description。

自查：**描述里没有第 ③ 条，这个 skill 大概率会被误触发。**

### 触发词表（§6.4）

用户不会说「请调用 auth-account-src-report」，用户会说「看看能不能盗号」。
所以路由靠的是**触发词表**，不是文件名。

本库这份记忆里，这张表就是 `registry/ROUTING.md` 的 **Trigger Table**，三列：

```
| Trigger / 触发条件 | Read | What it gives you |
```

写法要求：

| 列 | 写成什么 | 反例 |
| --- | --- | --- |
| ① 触发条件 | **用户原话**，用引号包起来；同一形态的几种说法并列 | 写文件名 `memory/xxx.md` |
| ② Read | 读哪个文件的哪一节 / 哪条 PR | 写"相关文档" |
| ③ 给你什么 | 一句话摘要 + 一句实测背景 | 把正文抄一遍 |

```
| **"这个目标怎么什么都能 200"、"我是不是被软 404 骗了"** | `memory/layer-4-long-term.md` **§Targets That Answer Everything** | 全路径同哈希降落壳的判据：去掉鉴权后响应不变 ⇒ 该端点不是鉴权边界 |
```

> 触发条件的写法是整个路由的成败点。表里写成文件名，AI 就永远命中不了它。

### 唯一 owner（§6.4）

一个问题只能有一个负责人，否则两个都像总控的 skill 会各自维护一份状态、互相覆盖。

写清两件事：**谁是 owner**、**我交出什么**。

```
全流程编排 → auto-pentest-router（唯一 owner：持有证据地图、状态、阶段推进）
本 skill    → 只负责本专项，不建第二套流程
```

约束句是两句：「把全流程编排交给 <owner>」「不创建第二份证据地图 / 第二套阶段状态」。

### overlay：横切规则不抢入口（§6.4）

有些规则对所有场景都适用，但它本身不是一个任务 —— 比如「深入任何一条链之前先做一轮最小化分诊」。

这类**不该当主入口，该当叠加层**。判据：**到处都该用、但不该当主入口 → 它是 overlay**。
在回归用例里给它单开一个字段，而不是硬塞进 primary：

```json
{ "expected_primary": [...], "expected_supporting": [...], "expected_overlay": ["proactive-injection-triage"], "avoid_skills": [...] }
```

## 第 5 步 · 测：带和不带的对照（§6.3）

```
测试题 → 带 Skill 跑 → 结果 A
       → 不带 Skill 跑 → 结果 B
             A 比 B 好吗
```

- 题目必须有**明确正确答案**，否则没法比
- 两组输出都要记录，**不要只记结论**
- 带手册明显更好 → 留；差不多 → 换个更难的题再测；**带手册更差 → 直接删，别修**

### avoid 才是重点（§6.4）

只测正向会导致一个后果：为了让每个用例通过，描述越写越宽，最后每个 skill 都被触发，路由彻底失效。

**所以必须同时测"不该触发的没触发"。**

回归用例四个字段：`primary` / `supporting` / `overlay` / `avoid`。
`avoid` 挑最容易被误触发的那个：词面重叠的，或上一个用例的 primary（防上下文串味）。

---

## 第 6 步 · 停：什么情况下不许写

命中任一条，**停下，不要落盘**：

- AI 已经会，且不需要排序纪律
- 价值分 < 7
- 拿不出带/不带对照，或对照结果是"更差"
- 写不出第 ③ 段排他声明
- 写出来全是原理，没有判断流程

---

## 第 7 步 · 收尾自查六问（§7）

落盘前用这六个问题过一遍。**任何一问答不上来，就别写。**

| 问 | 自查什么 | 不合格的样子 |
| --- | --- | --- |
| **为什么写** | 写的是 AI 不会的，还是纪律 | 抄了一遍原理 |
| **写什么** | 该做成 Skill、五段框架，还是不写 | 什么都做成 Skill |
| **写给谁** | description 写清楚了吗 | 描述空泛，没有触发条件 |
| **什么时候写** | 说清什么时候别用我了吗 | 没有排他声明 |
| **写在哪** | 放对层了吗 | 排他声明写进了 references |
| **怎么写** | 是判断流程还是知识复述，测过吗 | 只有原理，没测过 |

两道额外闸门（本库特有）：

| 闸 | 判据 |
| --- | --- |
| **进路由表了吗** | `registry/ROUTING.md` 的 Trigger Table 里有一行能命中它；没有就是"写了也没人读" |
| **证据进 skill 了吗** | 原始请求/响应、截图必须留在 case 目录，skill 里只放方法 |

## 输出格式

判定完必须按这个结构回话，不要自由发挥：

```json
{
  "screen":   { "total": 0-10, "breakdown": {...}, "pass": true },
  "decide":   { "form": "skill|five-part|none", "dest": "...", "reason": "..." },
  "write":    { "blockers": [...], "warnings": [...] },
  "test":     { "cases": N, "withAvoid": true, "worseThanBaseline": false },
  "verdict":  "写|不写|改后再写",
  "nextAction": "一句话，人话"
}
```
